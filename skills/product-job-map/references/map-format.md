# Формат для существующей доски

Читай перед сохранением карты. Это формат данных, не способ придумать работы.
UI и API уже существуют: не создавай новый HTML, React Flow-прототип или копию консоли.

Рабочий файл `reports/job-map/<run>/map.json` — обычный JSON, который читает консоль;
его нельзя заменить сжатым диагностическим архивом. Один narrative-отчёт рядом.
Диагностика и review — отдельные внутренние материалы, исходники не переписываются.

Корень:

```json
{
  "version": 1,
  "title": "Карта работ продукта",
  "basis": "Гипотезы из описания продукта; реальные случаи ещё не исследованы.",
  "scope": {"productId": "product-id", "goal": "Выбрать работы для исследования", "edition": "full"},
  "editions": {"full": "Текущий продукт", "public": "Отдельная версия не описана"},
  "jobs": {},
  "graphs": [],
  "contexts": [],
  "sources": {},
  "inventory": [],
  "review": {"status": "unreviewed", "sourceRefs": []}
}
```

`jobs` — объект по устойчивым ID. Одна запись:

```json
{
  "id": "job-choice", "label": "Выбрать следующий выпуск",
  "kind": "original", "originalLabel": "исходная формулировка при её наличии",
  "description": "Что человек пытается изменить и в какой ситуации.",
  "input": "Что нужно для этой работы.", "output": "Проверяемый результат работы.",
  "mechanism": "Как вклад продукта может улучшить результат и при каком условии.",
  "alternatives": "Нынешний способ; если неизвестен — явно гипотеза или пробел.",
  "basis": "hypothesis", "sourceRefs": ["product-description"],
  "full": {"state": "assist", "contribution": "Конкретная помощь продукта.",
    "limit": "Что не обеспечивается.", "sources": ["product-description"]},
  "public": {"state": "unknown", "contribution": "Отдельная версия не описана.",
    "limit": "Возможности этой версии неизвестны.", "sources": []}
}
```

`kind`: `original` (входной список), `higher` (верхняя работа фрагмента), `bridge`
(добавленная связующая работа), `external` (внешнее исполнение), `proposed` (идея
расширения). Это роль в документе, **не** уровень Big/Core/Small/Micro.
`basis`: `hypothesis`, `owner`, `source`; оно описывает происхождение, не качество.
`sourceRefs` ссылаются на существующие записи `sources`.

`full` и `public` — слоты редакций предложения: `full` — основное текущее предложение,
`public` — отдельно описанная бесплатная/публичная версия, если она реально есть.
`scope.edition` (необязательно, `full` или `public`) называет выбранный охват этой
карты — какой слот консоль показывает как основной. Для обычного продукта с одним
предложением используй `"edition": "full"` и записывай известный вклад в `full`;
слот `public` оставь `unknown` без выдуманной отдельной версии. Если владелец явно
исследует реально существующую бесплатную версию — выбери `"edition": "public"` и
заполни именно её охват. Никогда не выдумывай коммерческую редакцию и не
копируй значения одного слота в другой как «примерно то же». При обновлении карты
сохраняй фактические значения обоих слотов и сохранённый выбор edition; карты без
`scope.edition` читаются по умолчанию как `full`.
`state`: `ready` — есть названная действующая процедура; `assist` — помощь с частью;
`change` — нужна доработка; `external` — требуется действие за пределами продукта;
`unknown` — возможностей не установили. У `change` добавь `change` с конкретным
изменением. Наличие процедуры не доказывает лучший результат у покупателя.

`graphs`: `{id,title,jobIds,edges,note,boundary}`. `id` совпадает с ID верхней работы
этого фрагмента, она включена в `jobIds`. Рёбра `{from,to,why,basis,sourceRefs,condition?}`
идут **от средства к цели**. Любая показанная работа должна иметь путь к верхней;
нет достоверной связи — отдельный фрагмент с пояснением, а не выдуманное ребро.
Не делай цикл из альтернативных вариантов, не записывай календарную последовательность
как «чтобы». `condition` сохраняет условия конкретного пути. `boundary` объясняет,
какой конечный результат продукт здесь не выполняет. Один job ID может встречаться
в нескольких фрагментах; равные слова сами по себе не основание объединять работы.

`contexts`: `{id,segmentId?,ideaId?,graphs,jobIds,excludedJobIds?,reason}`.
Пустой массив допустим, когда сегменты ещё не созданы. Новые группы людей до их
оформления сохраняй в отчёте, а не как ссылки на несуществующие профили.
`segmentId` — настоящий ID профиля; `ideaId` — настоящий ID отложенной идеи
(`artifactId:ideaId`). Ровно один из них. `reason` объясняет именно эту связь.
Связь через `graphs` остаётся предварительной и не означает принадлежности каждой
работы. `jobIds` — отдельно предложенные связи с конкретными работами.
Не записывай здесь общие `criteria`: reader берёт условия и критерии из точного
актуального профиля сегмента. Его критерии не становятся критериями каждого job.

`sources`: объект по ID, записи `{kind,title,text,path?,url?,document?}`.
Текст описывает источник и предел его применения. `path` — точный существующий путь
в workspace, без приписки «(строки...)». `document` — необязательный точный локальный
снимок, не пересказ под видом оригинала. Не скачивай источник ради заполнения схемы.

Если на входе был список работ, `inventory` сохраняет **каждый** пункт:
`{id,text,jobIds,reason}`. При объединении у нескольких исходных пунктов может быть
один job ID, но требуется объяснить равенство смысла. Для явно исключённого из scope
пункта: `decision: "out_of_scope"`, пустые `jobIds` и конкретная причина; покажи его
в отчёте. Не сокращай молча список из-за объёма. Если списка не было, `inventory: []`.

При существующем исследовании исходный список дополняется всеми работами из
`research-inputs.json` по [правилу покрытия](evidence-coverage.md). Для каждой
сохрани экспортированные `id` (`research:<recordId>`), `text` и объект `evidence`
без изменений; добавь `jobIds`, `reason`, `sourceRefs`. `evidence` сохраняет версию
записи, случай, актора и цитируемые основания. `sourceRefs` должны вести к
соответствующему снимку/основанию из `sources` и присутствовать у связанной работы.
Для таких строк `out_of_scope` недопустим: работа остаётся на карте, даже если
продукт её не выполняет. Одна строка на каждый случай сохраняется и при общем
job ID. Отдельные гипотезы не требуют выдуманных ссылок на респондентов.

`review`: `status: unreviewed|reviewed`, `sourceRefs` на сохранённый разбор. Не
выдавай самопроверку за независимый review. Проверяющий должен назвать возражения и
их решения; валидная схема и согласие моделей не означают подтверждённый спрос.

## Проверка и регистрация

Из checkout Product OS:

```sh
node skills/product-job-map/scripts/check-map.cjs <workspace> reports/job-map/<run>/map.json
```

С установленным навыком запускай тот же script внутри его `scripts/`. Общий runtime
разрешается установщиком; не зашивай путь чужой машины. `--inventory <relative.json>`
сверяет карту с точным входным массивом `{id,text}`. `--require-reviewed` проверяет
наличие записи review, но не оценивает её качество.

`--research-inputs reports/job-map/<run>/research-inputs.json` сверяет сохранённый
вход с текущей версией исследования. При наличии workspace checker автоматически
проверяет все текущие зарегистрированные работы продукта: пропуск, исключение,
подмена исходного текста/случая/основания или отсутствие связи с узлом дают ошибку.
Проверка без workspace/реестра не подтверждает полноту по работам респондентов.
Незавершённое извлечение интервью остаётся отдельным предупреждением. Сохранённые
исторические карты остаются читаемыми; новое требование не переписывает их данные.

После смысловой проверки сохрани отчёт и примени обычный `graph-write`:

```json
{
  "schemaVersion": 1,
  "expectedRevision": 7,
  "source": "reports/job-map/run/report.md",
  "operations": [{"op":"node","node":{
    "id":"artifact-job-map-product","type":"artifact","label":"Карта работ",
    "status":"hypothesis",
    "data":{"confidence":"ai","artifactKind":"strategic-job-map","version":1,
      "productId":"product-id","mapPath":"reports/job-map/run/map.json",
      "mapSha256":"SHA256 точных байтов map.json"}
  }}]
}
```

Настоящие ID, ревизию и SHA получи из workspace. Используй ID прежнего активного
артефакта при обновлении: меняется указатель на новую версию, старый файл остаётся.
Если активных карт несколько, разреши конфликт явно. Проверяй существование продукта,
сегментов и идей через переданный graph; не создавай их для прохождения проверки.
`graph-write --dry`, затем apply и `--check`. Проверь GET `/api/strategic-jobs` и
открой раздел «Карта работ» в консоли (`#jobs`): все работы, связи, источник и возврат. Успешный JSON без
проверенного reader — незавершённая доставка в консоль.
