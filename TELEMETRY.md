# Аналитика Product OS Public

Product OS учитывает завершённые установки и обновления, а также сообщённые агентом
применения восьми базовых скиллов. Это помогает понять, какими возможностями пользуются
и какие версии установлены. При установке сбор явно объявляется в терминале.

Передаются только тип события, версия Product OS и фиксированное название базового
скилла для события применения. Содержимое продуктов, запросы и ответы, файлы и пути,
имена пользователей, токены, названия проектов и постоянные идентификаторы устройств
не передаются. Отдельный журнал аналитики не сохраняет IP и User-Agent. Запрос идёт
на сервер Product OS: `https://productos.izmailov.tech/_cli_event`.

Считаются события, не уникальные люди. Повторная установка той же версии событие не
создаёт; переход с уже установленной другой версии считается обновлением. Старые
установки без аналитики задним числом не восстанавливаются.

Применение скилла учитывается после первого содержательного результата по нему в
разговоре. Простое чтение SKILL.md, установка и изучение кода не являются применением.
Если агент пропустит предусмотренную команду, событие не поступит. Этот счётчик не
доказывает успешность результата или пользу для клиента.

## Отключение

Попросите агента: «Отключи аналитику Product OS». Команда:

```sh
node <tools>/bin/product-os.js telemetry off
```

`<tools>` — уже установленный runtime Product OS. Через установщик также можно:

```sh
npx --yes --package=github:izmailovilya/product-os-public product-os telemetry off
```

Настройка сохраняется в `~/.product-os/telemetry.json`, применяется к обоим агентам
и сохраняется при обновлении. `telemetry status` показывает состояние, `telemetry on`
включает сбор обратно. `DO_NOT_TRACK=1` и `PRODUCT_OS_TELEMETRY=0` отключают отправку
независимо от настройки. В CI и при запуске из Node.js --test отправка также отключена.

Запрос выполняется без повторов, с ожиданием не более 1,5 секунды. Ошибка сети,
недоступный сервер или отключённый сбор не отменяют установку и не мешают работе
навыка. Отключение не отправляется как отдельное событие. На сервере — закрытый журнал
с ротацией и сжатием, до 365 архивов с непустыми днями.

## Для агента

После первого содержательного результата данного базового скилла в текущем разговоре
учти одно применение:

```sh
node <tools>/bin/product-os.js telemetry skill-used <skill-name>
```

Бери абсолютный путь существующего runtime из инструкций установки. При первом учёте
в разговоре кратко сообщи: «Учту применение скилла: передаются только его название и
версия Product OS. Отключение — telemetry off или DO_NOT_TRACK=1». Передавай только
фиксированное имя из восьми базовых навыков; не добавляй к команде контекст продукта.
Не считай делегированные подзадачи, повторное чтение, каждый ответ в одном диалоге или
проверку кода отдельными применениями. Если учёт пропущен, завершай основную задачу.
