# Product OS

Это рабочее место продукта. Используй его цель, ограничения и имеющиеся сведения
из PRODUCT.md; не задавай заново вопросы с уже сохранёнными ответами.

## Доступные навыки

- `os-setup`: создать или восстановить рабочее место без потери существующих данных.
- `product-context` («Добавить контекст»): сохранить принесённые материалы с источниками.
- `product-status` («Где мы и что дальше»): прочитать накопленное и предложить следующий шаг.
- `product-research` («Проверь один вопрос»): проверка одного выбранного вопроса по открытым
  источникам с сохранением отчёта, фактов, контраргументов и неизвестного.
- `product-segment-hypotheses` («Предложи сегменты»): карта возможных клиентов с независимой
  проверкой; без независимого критика результат помечается непроверенным черновиком.
- `product-job-map` («Карта работ»): стратегическая карта работ с вкладом и пределами продукта.
- `product-brand-identity` («Сформируй айдентику»): бриф, направления, логотип, система бренда.
- `product-reference-library` («Собери референсы»): библиотека примеров «как другие решают
  задачу» с источниками и проверкой.

Обработка интервью, глубокое исследование рынка, контент и разработка в Product OS не входят.

## Свои навыки

По просьбе создать, добавить, изменить или опубликовать пользовательский навык
прочитай CUSTOM-SKILLS.md из установленного runtime. Команды `skills` добавляют
расширение отдельно от базовых навыков и сохраняют его при обновлениях.
После успешной проверки нового навыка на примере вызови `skills offer`: предложи
подготовить PR только при `shouldAsk: true`; отказ сохрани через `skills decline`.
Публикуй только после разрешения на конкретный проверенный пакет, сохраняя авторство.

## Файлы

PRODUCT.md — паспорт; sources/ — оригиналы; reports/ — производные заметки;
research-graph.json — структурированная память; MOVES.md — выбранные действия;
IDEAS.md — пока не выбранные идеи. Читай только относящийся к вопросу срез.

Различай факты, слова владельца, наблюдения и гипотезы. Сохраняй точные источники,
не выдумывай клиентов, платежи, результаты или подтверждение спроса.
Записывай память общим writer, не переписывай JSON вручную. Совет не создаёт задачу.
Сохраняй существующие инструкции и данные. Не публикуй материалы без поручения.

## Запуск

По просьбе поделиться консолью с командой прочитай SHARING.md из runtime.
Предложи открытый доступ или пароль, рекомендуя пароль для приватных данных.
Повторно уже данный выбор не спрашивай. Команда получает только просмотр снимка;
подготовка локального пакета не публикует данные. Пароль запрашивай защищённым
вводом, не в чате. Публикуй после просмотра содержимого в пределах поручения.

Сначала ищи runtime в `.claude/skills/product-os-tools` внутри продукта, затем
в `~/.claude/skills/product-os-tools` в домашней папке пользователя. Если его нет,
проверь окружение второго агента. Проверяй наличие `bin/product-os.js` и используй
абсолютный путь. Общие скиллы и инструменты не нужно копировать в этот продукт.
Команды: `node <tools>/bin/product-os.js help` и
`node <tools>/bin/product-os.js <workspace>` для локальной консоли.
Интерфейс читает общую память; не создавай отдельный dashboard для одного отчёта.

Выполняй порученное до проверяемого результата; называй ограничения честно.
Вопрос о сохранённых данных остаётся чтением. Следующий шаг предлагай по цели
владельца, не запускай новое исследование по собственной инициативе.
